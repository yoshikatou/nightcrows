## 実施内容

### 1. Raspberry Pi Pico USB HID マウスコントローラー実装

PC に接続した Pico を USB HID マウスデバイスとして動かし、PC マウス操作の自動化を実現。

**作成ファイル:**
- `pc/pico/code.py` — CircuitPython ファームウェア（CIRCUITPY に書き込み）
- `pc/pico_mouse.py` — `PicoMouse` クラス（Python ホスト側）
- `pc/move_test.py` — インタラクティブテストツール
- `pc/pico_ping.py` — シリアルポート診断
- `docs/pc_pico_mouse.md` — 設計書

**主要仕様:**
- COM ポート: COM4=data, COM5=console（sys.stdin）→ console 側を使用
- VID: 0x239A (CircuitPython) + 0x2E8A (MicroPython) 両対応
- コマンド: PING / HOLD L/R/M / RELEASE [btn] / CLICK L/R/M [ms] / MOVE dx dy
- キャリブレーション: `calibrate()` で実際の px/HID比率を計測し補正
- イーズアウト: `dist // 3` で目標に近づくほど減速
- フィードバック補正: `GetCursorPos` で実際着地位置を計測し微補正

### 設計上の決定事項

**座標系:** ウィンドウクライアント領域に対する相対比率（0.0〜1.0）を採用。  
→ ゲームウィンドウの解像度・位置変更に追従できる。`win32gui.GetClientRect + ClientToScreen` で毎ステップ変換。

**swipe の所要時間制御:**  
`duration_ms` から `n_steps = dist // 15`、`step_delay = duration_ms / 1000 / n_steps` を計算して `PicoMouse.move_to()` に渡す。HID のイーズアウト（残距離 // 3）と組み合わせてゲームのスワイプに近い動きを実現。

**mobile 版フロー JSON との互換:**  
`pc_flow.py` は `mobile/gui/flow.py` の `ScheduleEntry` / `FlowSettings` / `PcFlow` を PC 単体で動くよう再実装。JSON フォーマットは同一なので mobile 版のフロー設定を流用できる。

**Pico 未接続時のフォールバック:**  
`from pico_mouse import PicoMouse` を `try/except ImportError` でラップ。Pico がなくても GUI は起動し、tap/swipe ステップのみスキップ（ログ記録あり）。

**起動時スケジュールスキップ:**  
フロー開始時刻より前のエントリを `last_fired` に登録し重複実行を防ぐ。再起動直後に前の時間のシーンが二重実行されない。
