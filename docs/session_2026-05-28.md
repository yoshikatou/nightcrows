## 主要な実装内容

### 1. `last_due_scenes` に昨日フォールバックを追加 (`pc/gui/pc_flow.py`)

**問題:** 深夜帯（例 03:35）に発火した場合、当日の有効エントリが現在時刻より前にまだ一つも無く、`None` 返却でスキップされていた。

**修正:**
- `_due_scenes_on(flow, target_date, max_hm_exclusive)` ヘルパーに候補抽出を切り出し
- `last_due_scenes` は 1. 今日 (`time < now`) → 2. 昨日 (`time < "99:99"`) の順で探索
- 各日内で最も時刻が遅いエントリを採用

5/28 03:35 のケースでは、フロー `基本_pc.json` の daily `06:10 DQ` が当日候補に無かったが、昨日 5/27 (水) の daily `06:10` が拾えるようになる。

詳細は `docs/flow_design.md` の「`restart_scene` のフォールバック動作」セクション参照。

### 2. ウォッチャー発火→ハンドラー完了の自動録画 (`pc/gui/pc_flow.py`, `pc/gui/recorder.py`, `pc/gui/pc_main.py`)

**動機:** 「どこまで動作していたのか」を後追い確認したい。発火時の handler シーンが想定どおり進んだか、止まった箇所はどこかを録画で検証する。

**実装:**
- `WindowRecorder.start(hwnd, fps, prefix="rec")` に `prefix` 引数を追加。出力ファイル名が `{prefix}_YYYYMMDD_HHMMSS.mp4` になる
- `PcFlowRunner.set_recorder(recorder, fps)` で `pc_main` の既存 `WindowRecorder` を共有
- `_handle_fired` の前後で `_start_auto_record` / `_stop_auto_record` を呼ぶ
  - 開始: 手動録画中（`recorder.is_recording`）でなければ `rec_watcher_<title>_...mp4` で開始
  - 停止: ハンドラーシーン完了直後（成功・失敗いずれでも `finally` で実行）
- 録画 fps スピンボックスの `valueChanged` を `set_recorder` に再接続して、変更が即時自動録画にも反映

**運用:**
- 死亡ウォッチャー発火 → 復活シーン完了までが 1 ファイル
- ファイル名にウォッチャータイトル（英数のみ・最大 24 文字）が入るので、手動録画と区別が容易
- 手動録画中の発火では自動録画はスキップ（既存セッションを尊重）

### 4. シーン編集の「選択行を実行」を複数選択対応 (`pc/gui/pc_scene_editor.py`)

**動機:** TeamViewer 接続時に再生の途中ステップだけが下にズレる事象の切り分けで、「特定の連続するステップだけを再生モードと同じ条件で走らせたい」ニーズがあった。

**修正:**
- `_list_steps` の SelectionMode を `ExtendedSelection` に変更（Ctrl/Shift クリックで複数選択可）
- `_run_selected_step` を多選択対応: 選択行を昇順で連続実行
- `_launch_thread` に `rows: list[int]` 引数を追加し、非連続選択でも正しくハイライト
- `_remove_step` も複数選択対応（DEL キーで選択全行をまとめて削除）

「▶ 再生」(全ステップ再生)はそのまま、「選択行を実行」が単発 → 複数連続実行に拡張された形。

### 3. `click_at` 安定待ち導入 → revert (`pc/pico_mouse.py`)

**経過:**
- TeamViewer 接続時の BF3 94LV ステップ 11 ズレ対策として `_settle_before_click` を導入（GetCursorPos 連続安定待ち + 補正 move_to）
- しかしローカル単発（1 行ずつ実行）でもズレが出るようになる副作用が出た
- 原因究明を優先するため、関連定数 + メソッド + click_at からの呼出を削除して **直前のシンプル実装へ revert**
- 今後の方針: 計測ログ（クリック後の実カーソル位置等）を増やし、ズレが発生する瞬間を特定してから対策を再検討

### 5. `if_image` ステップに then/else インライン手順を追加

**動機:** 「画像が見えたらクリック / 別アクション / なければ何もしない」のような分岐を、別シーンファイルに分けずに 1 つの if_image ステップ内で書けるようにする。

**バックエンド (`pc/gui/pc_scene.py`):**
- if_image の params に `then` / `else` (list[dict]) を追加
- 非空ならその場で `_dict_to_pc_step` で PcStep に変換して再帰 run_pc_scene (`depth+1`)
- 空または未指定なら従来の `then_scene` / `else_scene` (シーン名)
- 循環参照チェックは `_call_stack` を引き継ぎ

**編集 UI (`pc/gui/if_image_dialog.py` 新規, `pc/gui/pc_scene_editor.py`):**
- `IfImageEditDialog`: 2 つの `_BranchPanel` (成立時 / 不成立時) を持つ
- 各分岐: ラジオで「インライン手順 / シーン呼出 / 何もしない」を切替
- インライン手順は QListWidget + 追加メニュー (タップ / 待機 / キー入力 / シーン呼出) + 編集 / 並べ替え / 削除
- if_image ステップ選択 → 「⚙ 値編集」で起動
- `_step_label`: インライン時は `[インライン N 手順]` を表示

**インライン非対応:** tap_image / wait_image / swipe など位置指定を要するステップは現状インライン入力では扱わない（キャンバス前提のため）。必要なら `call_scene` で別シーンに切り出して呼ぶ運用。
